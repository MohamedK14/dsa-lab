Story time: the first computer bug

In 1947, engineers working on the Harvard Mark II computer found a moth stuck inside one of its relays, which was making it fail. They taped the moth into the logbook and wrote 'First actual case of bug being found.' People already called faults 'bugs', but the moth made the word famous. Every time your code misbehaves, you're in good company.

Dynamic Array

  • In a real array, a removed slot isn't erased, just ignored. The old value stays in memory until something overwrites it.
  • When the array is full, it can't grow in place. A bigger one is allocated, everything is copied over, and the old one is freed.
  • Doubling the capacity keeps full copies rare, so push_back averages out to O(1).

A row of numbered slots. When it fills up, it grows.

Think of it like a classroom

An array is a classroom with a fixed number of desks in a row, each with a number. Students fill the desks one by one. When the room is full and another student arrives, you can't squeeze in a desk. You find a bigger room (usually twice the size), walk every student over to it, and give the old room back. That move is the resize you see when the capacity doubles.

Stack

  • push, pop and top only ever touch the top, so each one takes O(1) time.
  • A stack is usually built on a dynamic array (the top is the last slot) or on a linked list.
  • Stacks power undo, the browser's back button, bracket matching, and the call stack that runs every program.

A pile where you can only add or remove at the top. Last in, first out (LIFO).

Think of it like a pile of plates

You put each clean plate on top of the pile, and when you need one you take it from the top too. The plate at the bottom went on first, but it's the last one you can reach. You never pull a plate out of the middle.

Queue

  • enqueue adds at the back and dequeue removes from the front, so the first one in is the first one out (FIFO). Looking at the front is O(1).
  • On a simple array, dequeue is O(n): every item shifts one slot forward. A circular buffer fixes this by moving a "front" index around a ring of slots instead, so dequeue becomes O(1).
  • Queues run print jobs, task schedulers, keyboard buffers and breadth-first search (the level-order traversal on the tree pages).

A line where you join at the back and leave from the front. First in, first out (FIFO).

Think of it like a line at a shop

New customers join the end of the line. The cashier always serves whoever is at the front, the person who has waited longest. Nobody cuts in, and nobody leaves from the middle. When one person is served, everyone behind them takes a step forward.

Linked List

  • push_front and pop_front only change the head pointer, so they take O(1) time.
  • This list only remembers its head, so push_back and search walk node by node and take O(n). Also storing a tail pointer would make push_back O(1).
  • Nodes can sit anywhere in memory. Nothing has to be copied for the list to grow, but you can't jump straight to the 5th item like you can in an array.

A chain of nodes. Each one holds a value and points to the next.

Think of it like a treasure hunt

Each clue gives you something and tells you where to find the next clue. You only know where the first one is. To reach the fifth clue you must follow the first four. Adding a new first clue is easy: write on it where the old first clue is hidden. The last clue says "the end".

Binary Tree

  • Every traversal visits each node exactly once, so it takes O(n) time.
  • Preorder, inorder and postorder go deep first. Level-order goes row by row and uses a queue.
  • A general binary tree has no ordering rule, so finding a value can mean checking every node: O(n). Inserting here also scans for the first free spot, O(n).

A tree where every node has at most two children, called left and right.

Think of it like a family tree

One person sits at the top. Under them are up to two children, who can have up to two children of their own. Each person hangs from exactly one parent. A traversal is a way of visiting every relative once, and the order you choose decides who you greet first.

Binary Search Tree

  • insert, search, delete, find min and find max each follow one path down the tree: O(log n) on average.
  • Worst case O(n): if values arrive in sorted order, the tree degenerates into a list. Try "Insert sorted 1..7".
  • An in-order traversal visits every node once, O(n), and returns the values in sorted order.

AVL Tree

  • search, insert and delete always take O(log n) time, even when the values arrive in sorted order.
  • A node's balance factor is the height of its left subtree minus the height of its right subtree. An AVL tree keeps every one at -1, 0 or +1.
  • A rotation moves the taller side up and the shorter side down while keeping the sorted order. It only changes a few pointers, and it stops the tree from growing tall.

A binary search tree that rotates itself whenever one side gets too tall.

Think of it like a seesaw

A little difference in weight between the two ends is fine. When one end gets much heavier, you shift the pivot toward the heavy side until it levels out. Every node in this tree is a small seesaw, and a rotation is how it moves its pivot.

Red-Black Tree

  • The 5 rules:
    1. Every node is red or black.
    2. The root is black.
    3. Empty spots below the leaves count as black.
    4. A red node never has a red child.
    5. From any node, every path down to an empty spot passes the same number of black nodes.
  • Those rules keep the height small, so search and insert take O(log n) time. So does delete, which this page leaves out.
  • Many standard libraries use it for sorted maps and sets, such as Java's TreeMap and most versions of C++ std::map.

A search tree that colours its nodes red or black to stay balanced.

Think of it like a club with strict seating rules

Every member wears a red or a black badge. The head of the room wears black, two red badges may never sit directly one above the other, and every route to an empty chair must pass the same number of black badges. When a newcomer breaks a rule, members swap badges or change seats until the rules hold again.

Sorting

  • Bubble, insertion and selection sort take O(n²) time on average. Bubble and insertion sort drop to O(n) on data that is already sorted.
  • Merge sort always takes O(n log n) and needs O(n) extra memory.
  • Quick sort takes O(n log n) on average and O(n²) in the worst case, when the pivots are bad.

Five ways to put numbers in order. Watch how differently they work.

Think of it like lining people up by height

You can let neighbours swap until nobody is out of order (bubble), slide each newcomer into the right spot (insertion), keep calling out the shortest person left (selection), merge two lines that are already sorted (merge), or pick one person and send shorter people to one side and taller to the other (quick).
